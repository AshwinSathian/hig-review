## Typography (added the same day)

`scripts/type-eval.js` has five unit tests (test/type-eval.test.mjs) and was run on real faces: Inter Variable, Atkinson Hyperlegible Next and JetBrains Mono from Wayfarer's `@fontsource` packages, in Chromium, Firefox and WebKit at 12 and 13 px, plus magnified 1× renders.

- It found what the eye then confirmed: Inter's capital I and lowercase l render identically at 12 and 13 px (0 device pixels apart in Chromium and Firefox), and Inter's `cv05`/`cv08` alternates have no effect in that build. Atkinson has no confusable pair and has tabular figures; JetBrains Mono's dotted zero is 1 device pixel from O at 12 px on a 1× display.
- Two defects in the first version, both fixed before use: `document.fonts.check` returns true for a family with no faces (now: `loaded` comes from the faces or from rendering), and width-based coverage over-reported scripts the system falls back to (now: the faces' `unicode-range` decides when declared, and the method is reported). A third: the file list counted the subsets the script itself loads; it now reads the list first.
- The pixel distance alone under-weights small marks (a dotted zero scored 0.04); the output now also gives `px`, the device pixels that differ, and the reference says `px` 0 is a fail and a low distance with `px` above 0 is a check by eye.

Case E rerun with the typography reference (Playwright, Chromium only): PASS. 15 findings (2 Blockers, pixel-sampled glass contrast confirmed one), 3 reworks (premise, identity, system), 5 enhancements, 2 directions. The Type section ran `type-eval.js` three times: it found the declared Inter never loads (0 font files), measured what renders instead (system-ui: I/l 0 pixels apart at 14 to 16 px; tide table not tabular), and measured candidate faces from Google Fonts before proposing them (Public Sans I/l 1 to 2 pixels apart, CONCERN; IBM Plex Sans and Atkinson Hyperlegible Next PASS). That run led to two script fixes reviewed below: a not-loaded family now reports its measurements against the page's own fallback (`renderedWith`), so the second manual run is no longer needed.

A separate review of the whole change found four script defects, all fixed with tests: `-apple-system` and `BlinkMacSystemFont` were quoted and so measured as missing fonts; family names were matched case-sensitively; faces that failed to load counted toward coverage; rendering-based coverage of local fonts over-reported every script (engines fall back per character whatever the stack says), so local fonts now report Latin only and the other scripts as unknown. Its rule findings were fixed too: leftover "never name a face" lines, a forced minimum of four enhancements, an undefined peer-gap margin and a System condition any app could meet, Impact floors set by Taste lines, and gaps in the whole-app split (the Stance section and type-eval output for subagents, renumbering after the red team).
